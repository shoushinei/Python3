2.1実行環境構築 1問

Python本体のインストールと、仮想環境・パッケージ管理の仕組みを説明します。

2.1.1Python公式版をインストール

Pythonは公式サイト（python.org）からダウンロードしてインストールできます。インストールできたら、ターミナルでバージョンを確認します。

% python3 -V
Python 3.13.2

Windowsでは py や python コマンドを使います。

2.1.2venv: Pythonの仮想環境

プロジェクトごとに、使うパッケージとそのバージョンを分けておく仕組みを仮想環境と呼びます。標準ライブラリの venv で作れて、Windows・macOS・Linuxのどれでも使えます。

% python3 -m venv env              # env という名前の仮想環境を作る
% source env/bin/activate          # 有効化（macOS / Linux）
(env) % python -V                  # プロンプトの先頭に (env) が付く
Python 3.13.2
(env) % deactivate                 # 無効化

Windowsでは env\Scripts\activate で有効化します。

注意：venvで分かれるのはパッケージ

仮想環境の中のPythonは、venvを実行したPython本体と同じバージョンになります。venvは「パッケージの組み合わせ」を分ける仕組みで、Pythonのバージョン自体を切り替える仕組みではありません。別のバージョンを使いたいときは、そのバージョンのPythonを別にインストールして、そのPythonでvenvを作ります。

2.1.3pipコマンド

pip は、PyPI（The Python Package Index）に公開されているパッケージをインストールするためのコマンドです。

(env) % pip install numpy             # インストール
(env) % pip install pandas==2.2.3     # バージョンを指定してインストール
(env) % pip install -U numpy          # 新しいバージョンに更新
(env) % pip list                      # インストール済みのパッケージ一覧
(env) % pip freeze > requirements.txt # 一覧をファイルに書き出す
(env) % pip install -r requirements.txt  # ファイルの一覧をまとめてインストール
(env) % pip uninstall numpy           # アンインストール

2.1.4Anaconda

Anaconda は、Anaconda社が開発・配布しているPythonのディストリビューションです。NumPy や pandas など、データ分析でよく使うパッケージが最初からまとめて入っています。

  • パッケージ管理と仮想環境の作成には、pip・venv ではなく独自の conda コマンドを使います（例：conda create -n myenv python=3.12）。
  • conda では、仮想環境ごとにPythonのバージョンを指定できます。
  • pip と conda を同じ環境で混ぜて使うと、依存関係が崩れることがあるので注意が必要です。
POINT
  • venv：標準ライブラリ。パッケージを環境ごとに分ける。
  • pip：PyPI からパッケージをインストールする。
  • Anaconda：Anaconda社のディストリビューション。conda で環境とパッケージを管理する。
