10.1OSインターフェイス

os モジュールには、オペレーティングシステムとやり取りする関数が数多くあります。

In
import os
os.getcwd()                    # 現在の作業ディレクトリを返す
os.chdir('/server/accesslogs') # 作業ディレクトリを変える
os.system('mkdir today')       # システムのシェルでコマンドを実行する
本番で出た論点：from os import * を使ってはいけない理由

チュートリアルには、from os import * ではなく import os の形を使うようにと書かれています。理由は、os.open() が組み込み関数の open() を隠してしまう（上書きしてしまう）からです。この2つは動作がまったく違います。

In
import os
print(open)                         # 組み込みの open
from os import *                    # os の名前が全部入ってくる
print(open is os.open)              # open が os.open に置き換わった
try:
    f = open('memo.txt')            # いつものつもりで呼ぶと…
except TypeError as e:
    print("TypeError:", e)
Out 
<built-in function open>
True
TypeError: open() missing required argument 'flags' (pos 2)

os.open() は低レベルのファイル操作の関数で、フラグ（開き方）を指定する引数が必須です。from os import * のあとでは、open('memo.txt') と書いたつもりが os.open('memo.txt') になり、エラーになってしまいます。import os なら、open()（組み込み）と os.open() をはっきり区別できます。

In
import builtins
open = builtins.open                # 上の例で上書きした open を元に戻す
import os
print([n for n in dir(os) if n.startswith('get')][:5])   # dir(os) で関数の一覧が見られる
Out 
['get_blocking', 'get_exec_path', 'get_inheritable', 'get_terminal_size', 'getcwd']

os のように大きなモジュールを使うときは、組み込み関数 dir()（関数の一覧）と help()（説明）が役に立ちます。

ファイルやディレクトリの日常的な管理には、より高水準のインターフェイスを持つ shutil モジュールが使いやすいです。

In
import shutil
shutil.copyfile('data.db', 'archive.db')        # ファイルのコピー
shutil.move('/build/executables', 'installdir') # 移動
