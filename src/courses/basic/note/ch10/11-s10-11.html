10.11品質管理

質の高いソフトウェアを作るには、関数ごとにテストを書き、開発中に頻繁に実行することが大切です。

doctestモジュールを走査して、docstring の中に書いたテストを検証する。docstring の例を実際に動かして、書いてある結果と一致するか調べる。
unittestdoctest より包括的なテストを、別のファイルで管理できる。
In
def average(values):
    """Computes the arithmetic mean of a list of numbers.

    >>> print(average([20, 30, 70]))
    40.0
    """
    return sum(values) / len(values)

import doctest
doctest.run_docstring_examples(average, {'average': average}, verbose=True)
Out 
Finding tests in NoName
Trying:
    print(average([20, 30, 70]))
Expecting:
    40.0
ok

通常は、モジュールの最後で doctest.testmod() を呼ぶと、そのモジュールの docstring にあるテストが自動で検証されます。上の例は、この教材の実行環境で動かすために、1つの関数の docstring だけを検証する関数を使い、verbose=True で途中経過を表示しています（テストが失敗すると、期待した値と実際の値が表示されます）。

In
import unittest

class TestStatisticalFunctions(unittest.TestCase):

    def test_average(self):
        self.assertEqual(average([20, 30, 70]), 40.0)
        self.assertEqual(round(average([1, 5, 7]), 1), 4.3)
        with self.assertRaises(ZeroDivisionError):
            average([])
        with self.assertRaises(TypeError):
            average(20, 30, 70)

unittest.main()  # コマンドラインから呼び出すと、すべてのテストを実行する
.
----------------------------------------------------------------------
Ran 1 test in 0.000s

OK

unittest.TestCase を継承したクラスに test_ で始まるメソッドを書き、assertEqual や assertRaises で結果を確かめます。

Javaと比べると

unittest は JUnit とほぼ同じ作りです（TestCase クラス、assertEqual、assertRaises ≒ assertThrows）。doctest にあたるものは Java にはなく、「ドキュメントに書いた使用例がそのままテストになる」のが特徴です。
