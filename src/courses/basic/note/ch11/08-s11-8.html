11.810進数の浮動小数点計算

decimal モジュールの Decimal 型は、10進数の浮動小数点数の計算をします。組み込みの float（2進数の浮動小数点数）と比べて、次の用途に向いています。

  • 金融のアプリケーションなど、10進数で正確に表す必要があるもの
  • 精度を制御したい、法律や規則で決まった丸め方をしたい場合
  • 有効桁数を追跡したい場合、手計算と結果を一致させたい場合
In
from decimal import Decimal, getcontext
print(round(Decimal('0.70') * Decimal('1.05'), 2))   # 10進数で計算
print(round(.70 * 1.05, 2))                          # float では誤差で 0.73
print(Decimal('1.00') % Decimal('.10'))
print(1.00 % 0.10)
print(sum([Decimal('0.1')] * 10) == Decimal('1.0'))
print(sum([0.1] * 10) == 1.0)                       # Python 3.12 以降は True（下の注を参照）
print(0.1 + 0.1 + 0.1 == 0.3)                       # float の誤差で False
getcontext().prec = 36                               # 精度を36桁に
print(Decimal(1) / Decimal(7))

チュートリアル（第4版）では sum([0.1]*10) == 1.0 は False と説明されています。Python 3.12 から、float の sum() が誤差を補正する計算方法に変わったため、現在の版では True になります。float の誤差そのものは、0.1 + 0.1 + 0.1 == 0.3 が False になることで確かめられます。試験ではチュートリアルの説明（False）を基準に考えましょう。

  • Decimal の計算結果は、末尾の0も保持されます（2桁の数同士の掛け算から、4桁の有効桁数を推定する）。
  • float では表せない値も正確に表せるので、剰余の計算や等しいかの判定が、手計算どおりになります。
Javaと比べると

Decimal は Javaの BigDecimal にあたります。Decimal('0.1') のように文字列から作るのも、new BigDecimal("0.1") と同じ理由です（float から作ると誤差ごと取り込んでしまう）。
