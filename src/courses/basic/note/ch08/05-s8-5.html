8.5例外の連鎖

ある例外が原因で別の例外を送出するときは、raise 新しい例外 from 元の例外 と書いて、原因を明示できます。

In
def func():
    raise ConnectionError

try:
    func()
except ConnectionError as exc:
    raise RuntimeError('Failed to open database') from exc
Traceback (most recent call last):
  File "t1.py", line 4, in <module>
    func()
  File "t1.py", line 2, in func
    raise ConnectionError
ConnectionError

The above exception was the direct cause of the following exception:

Traceback (most recent call last):
  File "t1.py", line 6, in <module>
    raise RuntimeError('Failed to open database') from exc
RuntimeError: Failed to open database
  • from を書かなくても、except 節や finally 節の中で例外が起きると、自動で連鎖します。そのときは「During handling of the above exception, another exception occurred:」と表示されます。
  • from None と書くと、自動の連鎖を無効にできます（元の例外は表示されない）。
  • 連鎖した元の例外は、新しい例外の __cause__（from で明示したとき）や __context__（自動のとき）属性に入ります。
In
try:
    try:
        open('database.sqlite')
    except OSError:
        raise RuntimeError("unable to handle error")
except RuntimeError as e:
    print(type(e.__context__).__name__)    # 自動で連鎖した元の例外
try:
    try:
        open('database.sqlite')
    except OSError:
        raise RuntimeError from None
except RuntimeError as e:
    print(e.__cause__, e.__suppress_context__)   # from None で連鎖が抑えられる
Out
