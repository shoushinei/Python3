    出題 1問（2.5%）

    1.0Pythonの特徴

    チュートリアル1章に書かれているPythonの特徴を、そのままの言い回しで押さえます。
    Pythonを使うと何がうれしいか
    • シェルスクリプトやバッチファイルより、大規模なプログラムのための構造やサポートが多い。
    • C言語より、エラーチェックが多い。
    • 超高水準言語で、柔軟な配列や辞書（ディクショナリ）のような高水準のデータ型を最初から持っている。
    • プログラムを再利用できるモジュールに分割できる。標準モジュールも豊富。
    インタプリタ言語

    Pythonはインタプリタ言語です。コンパイルやリンクが不要なので、開発時間を節約できます。インタプリタは対話的に使えるので、言語の機能を試したり、使い捨てのプログラムを書いたり、電卓として使ったりもできます。

    短く読みやすく書ける3つの理由
    ① 高水準のデータ型複雑な操作を1つの文で書ける。
    ② インデントでグループ化文のまとまりを、開始・終了のカッコではなくインデントで表す。
    ③ 宣言が不要変数や引数の宣言をしなくてよい。
    拡張できる

    Cでプログラムを書ける人なら、新しい組み込み関数やモジュールを簡単に追加できます（拡張可能）。逆に、Cで書いたアプリケーションにPythonのインタプリタを組み込んで、拡張用・コマンド用の言語として使うこともできます。

    名前の由来

    名前は、BBCのコメディ番組「モンティ・パイソンの空飛ぶサーカス」から取られています。爬虫類のニシキヘビ（python）とは関係ありません。

    Javaと比べると

    Javaは javac でコンパイルしてから実行し、変数の型も宣言します。ブロックは { } で表します。Pythonはこの3点がすべて逆、と覚えると特徴を選ぶ問題で迷いません。

    POINT
    • インタプリタ言語で、コンパイル・リンクは不要。対話的に使える。
    • 短く書ける理由：高水準データ型、インデントによるグループ化、宣言不要。
    • Cで拡張できる／Cのアプリに組み込める。名前はモンティ・パイソンから。

    確認問題

    Q1Pythonの特徴として誤っているものはどれか。

    1. インタプリタ言語であり、コンパイルやリンクが不要である。
    2. 文のグループ化を、開始・終了のカッコではなくインデントで行う。
    3. 変数や引数は、使う前に型を宣言する必要がある。
    4. Cで書いた拡張モジュールを追加できる。
    変数や引数の宣言は不要です。これはPythonのプログラムが短く書ける理由の1つです。

    2.1インタープリタの起動

    インタープリタの起動・終了と、起動オプションを説明します。
    起動と終了

    インタープリタは、Unixでは通常 /usr/local/bin/python3.x にインストールされ、ターミナルで python3.x と打つと起動します。Windowsでは py コマンドも使えます。

    • 終了するには、一次プロンプトでEOF（ファイル終端）文字を入力します。Unixでは Ctrl+D、Windowsでは Ctrl+Z です。
    • または quit() と入力しても終了します。
    • GNU readline ライブラリに対応していれば、行の編集や履歴の呼び出しができます（→ 14章）。
    起動のしかた
    コマンド意味
    python3 script.pyスクリプトファイルを実行する
    python3 -c "コマンド" [引数]コマンド（文字列）を実行する。シェルの特殊文字が含まれるので、コマンドは引用符で囲むのが普通
    python3 -m モジュール [引数]モジュールのソースファイルをスクリプトとして実行する
    python3 -i script.pyスクリプトを実行した後に対話モードに入る

    2.1.1引数を渡す

    スクリプト名とその後ろの引数は、文字列のリストとして sys モジュールの sys.argv に入ります。import sys で使えます。リストの長さは必ず1以上です。

    起動のしかたsys.argv[0]
    python3 s.py x y's.py'（スクリプト名）
    スクリプト名も引数もなし''（空文字列）
    スクリプト名に -（標準入力）を指定'-'
    python3 -c "…"'-c'
    python3 -m hello見つかったモジュールのフルパス名

    実際に試すと、次のようになります。

    % python3 -c "import sys; print(sys.argv)" a b
['-c', 'a', 'b']
% python3 s.py x y            # s.py の中身は import sys; print(sys.argv)
['s.py', 'x', 'y']
% echo 'import sys; print(sys.argv)' | python3 - p q
['-', 'p', 'q']
% python3 -m hello z
['/tmp/mm/hello.py', 'z']

    -c コマンド や -m モジュール の後ろに書いたオプションは、インタープリタ自身のオプションとしては処理されず、そのまま sys.argv に入ります。

    Javaと比べると

    Javaの main(String[] args) の args には、クラス名は入らず引数だけが入ります。Pythonの sys.argv は、先頭（[0]）にスクリプト名が入る点が違います。引数そのものは sys.argv[1:] です。

    2.1.2対話モード

    コマンドを端末から読み込んでいる状態を対話モードと呼びます。

    • 次のコマンドを待っているときは一次プロンプト >>> が表示されます。
    • 複数行の構文（if文など）の続きを待っているときは二次プロンプト ... が表示されます。
    • 起動すると、最初のプロンプトの前に、バージョン番号と著作権表示から始まるメッセージが表示されます。
    >>> the_world_is_flat = True
>>> if the_world_is_flat:
...     print("Be careful not to fall off!")
...
Be careful not to fall off!

    2.2インタープリタとその環境

    2.2.1ソースコード・エンコーディング

    • Pythonのソースファイルは、デフォルトでは UTF-8 でエンコードされているものとして扱われます。
    • 標準ライブラリは、識別子（名前）にASCII文字だけを使っています。
    • 別の文字コードを使うときは、ファイルの1行目に次のような特別なコメントを書きます。
    # -*- coding: cp1252 -*-

    例外として、1行目がUnixの「シバン（shebang）行」の場合は、文字コードの宣言は2行目に書きます。

    #!/usr/bin/env python3
# -*- coding: cp1252 -*-
    POINT
    • 終了は Ctrl+D（Unix）／Ctrl+Z（Windows）、または quit()。
    • -c はコマンド文字列、-m はモジュールをスクリプトとして実行、-i は実行後に対話モード。
    • sys.argv[0]：通常はスクリプト名、引数なしは ''、標準入力は '-'、-c は '-c'、-m はモジュールのフルパス。
    • >>> が一次、... が二次プロンプト。デフォルトの文字コードは UTF-8、宣言は1行目（シバンがあれば2行目）。

    確認問題

    Q1python3 -c "import sys; print(sys.argv)" spam eggs を実行したときの出力はどれか。

    1. ['spam', 'eggs']
    2. ['', 'spam', 'eggs']
    3. ['import sys; print(sys.argv)', 'spam', 'eggs']
    4. ['-c', 'spam', 'eggs']
    -c を使ったとき、sys.argv[0] は '-c' になります。後ろの引数は sys.argv[1:] に入ります。

    Q2Pythonインタープリタに関する説明として正しいものはどれか。

    1. python3 -i script.py とすると、スクリプトを実行した後に対話モードに入る。
    2. 二次プロンプトは >>> である。
    3. ソースファイルのデフォルトの文字コードは Shift_JIS である。
    4. Windowsで対話モードを終了するには Ctrl+D を押す。
    二次プロンプトは ...、デフォルトの文字コードは UTF-8、Windowsの終了は Ctrl+Z（または quit()）です。

    Q31行目にシバン行 #!/usr/bin/env python3 があるファイルで、文字コードを宣言するコメントはどこに書くか。

    1. シバン行と同じ1行目の末尾
    2. ファイルの最終行
    3. 2行目
    4. どこに書いてもよい
    文字コードの宣言は通常1行目ですが、1行目がシバン行のときは2行目に書きます。

    対話モードの変数 _

    対話モードでは、最後に表示された式の値が変数 _（アンダースコア）に入ります。電卓のように計算を続けるのに便利です。_ は読み取り専用として扱い、自分で値を代入しないようにします（代入すると、組み込みの _ を隠す別のローカル変数ができてしまいます）。

    >>> tax = 12.5 / 100
>>> price = 100.50
>>> price * tax
12.5625
>>> price + _
113.0625
>>> round(_, 2)
113.06

    int・float のほかに、Decimal・Fraction や、虚数部に j を付けて書く複素数（例：3+5j）も扱えます。

    5.8シーケンスの比較、その他の型の比較

    同じ型のシーケンス同士は、辞書式順序で比べます。

    1. まず先頭の要素同士を比べ、違えばそれで大小が決まる。
    2. 同じなら次の要素同士を比べる。これを、どちらかのシーケンスが終わるまで続ける。
    3. 要素自体が同じ型のシーケンスなら、その中も辞書式に比べる（再帰的）。
    4. 全部同じなら、2つは等しい。片方がもう片方の先頭部分と同じなら、短い方が小さい。
    5. 文字列は、各文字の Unicode のコードポイントの大小で比べる。

    6.1.2モジュールの検索パス

    import spam とすると、インタープリタは次の順で探します。

    1. まず、その名前の組み込みモジュール（sys.builtin_module_names にあるもの）
    2. なければ、sys.path のディレクトリのリストから spam.py を探す

    sys.path は、次の場所から初期化されます。

    • 入力スクリプトのあるディレクトリ（ファイルを指定していないときはカレントディレクトリ）
    • 環境変数 PYTHONPATH（ディレクトリ名のリスト。書き方はシェル変数 PATH と同じ）
    • インストールごとのデフォルト（site-packages など。site モジュールが処理する）
    注意

    スクリプトのあるディレクトリは、標準ライブラリより前に検索されます。そのため、標準モジュールと同じ名前のファイル（例：random.py）を置くと、そちらが読み込まれてしまいます。シンボリックリンクに対応したファイルシステムでは、リンク先のスクリプト本体があるディレクトリが加えられ、リンクのあるディレクトリは加えられません。

    6.1.3「コンパイル済み」Pythonファイル

    • 読み込みを速くするため、Pythonはコンパイル済みのモジュールを __pycache__ ディレクトリに モジュール名.バージョン.pyc という名前でキャッシュします（例：__pycache__/spam.cpython-313.pyc）。
    • ソースの更新日時とコンパイル済みファイルを比べ、古ければ再コンパイルします。コンパイル済みファイルはプラットフォームに依存しないので、異なるOS間で共有できます。
    • 次の2つの場合は、キャッシュを確認しません：①コマンドラインから直接実行したモジュール（毎回コンパイルし、結果も保存しない）、②ソースのモジュールがない場合（ソースなしで配布するには、.pyc をソースのディレクトリに置き、ソースは置かない）。
    • コマンドラインの -O は assert 文を除去し、-OO は assert 文と __doc__（docstring）を除去します。
    • .pyc ファイルから読み込んでも、プログラムの実行が速くなるわけではありません。速くなるのは読み込みだけです。
    • compileall モジュールで、ディレクトリ内の全モジュールの .pyc を作れます。

    6.2標準モジュール

    Pythonには標準モジュールのライブラリが付いています（詳しくはライブラリリファレンス）。一部はインタープリタに組み込まれていて、winreg のように特定のOSでしか使えないものもあります。sys モジュールはすべてのインタープリタに組み込まれています。

    • sys.path は文字列のリストで、普通のリストとして変更できます。

sys.path.append('/ufs/guido/lib/python')   # 検索パスにディレクトリを追加

    6.4パッケージ

    パッケージは、A.B のような「ドット付きのモジュール名」でモジュールを整理する仕組みです。A.B は、パッケージ A のサブモジュール B を表します。

    sound/                          トップレベルのパッケージ
      __init__.py               sound パッケージを初期化する
      formats/                  ファイル形式の変換用サブパッケージ
              __init__.py
              wavread.py
              ...
      effects/                  音響効果用サブパッケージ
              __init__.py
              echo.py
              surround.py
              ...
      filters/                  フィルタ用サブパッケージ
              __init__.py
              equalizer.py
              ...

    __init__.py は、ディレクトリをパッケージとして扱わせるために必要なファイルです。中身は空でもよく、パッケージの初期化コードを書いたり、__all__ を設定したりもできます。

    import の書き方使い方
    import sound.effects.echosound.effects.echo.echofilter(…)（フルネームで参照）
    from sound.effects import echoecho.echofilter(…)
    from sound.effects.echo import echofilterechofilter(…)
    • from package import item の item は、サブモジュール・サブパッケージ・パッケージ内で定義された関数やクラスなど、どれでもかまいません。まずパッケージ内で定義された名前か調べ、なければモジュールとみなして読み込みます。見つからなければ ImportError です。
    • import item.subitem.subsubitem の形では、最後以外はすべてパッケージでなければなりません。最後はモジュールかパッケージで、クラス・関数・変数は指定できません。

    6.4.1パッケージから * をインポート

    from sound.effects import * としたとき、

    • パッケージの __init__.py に __all__ というリストが定義されていれば、そこに書かれたモジュール名がインポートされます。
    • __all__ がなければ、サブモジュールは自動ではインポートされません。インポートされるのは、パッケージ自体（__init__.py を実行）と、そこで定義された名前だけです。
    In
    import os, sys
sys.path.insert(0, ".")
os.makedirs("sound/effects", exist_ok=True)
open("sound/__init__.py", "w").close()
with open("sound/effects/__init__.py", "w") as f:
    f.write('__all__ = ["echo"]\n')            # * のときは echo だけ
with open("sound/effects/echo.py", "w") as f:
    f.write('def echofilter(): return "echo!"\n')
with open("sound/effects/surround.py", "w") as f:
    f.write('def surround(): return "surround!"\n')
from sound.effects import *
print(echo.echofilter())
print("surround" in dir())                     # __all__ にないので入らない
    Out 
    echo!
False

    チュートリアルは、from package import 特定のサブモジュール と書くのが推奨の書き方だとしています。

    6.4.2パッケージ内の相互参照

    • 絶対インポート：from sound.effects import echo
    • 相対インポート：先頭のドットで、現在のパッケージと親パッケージを表します。
    In
    # sound/effects/surround.py の中で
from . import echo                  # 同じパッケージ（effects）の echo
from .. import formats              # 親パッケージ（sound）の formats
from ..filters import equalizer     # 親パッケージの filters の中の equalizer

    相対インポートは、現在のモジュール名をもとに解決されます。メインモジュールの名前は常に "__main__" なので、メインモジュールとして使うモジュールでは、必ず絶対インポートを使います。

    6.4.3複数のディレクトリにまたがるパッケージ

    パッケージには __path__ という特別な属性があります。__init__.py のあるディレクトリ名を入れたリストで、これを変更すると、パッケージに含まれるモジュールやサブパッケージを探す場所を広げられます。めったに使いません。

    POINT
    • import fibo なら fibo.fib、from fibo import fib なら fib（fibo は使えない）。from … import * は _ で始まる名前以外を全部。as で別名。
    • from の後ろはモジュール（パッケージ）名、import の後ろはその中の名前。date は datetime モジュールの中。
    • モジュールは1セッション1回だけ読み込まれる（reload は importlib.reload）。スクリプト実行時は __name__ == "__main__"。
    • 検索順：組み込みモジュール → sys.path（スクリプトのディレクトリ → PYTHONPATH → デフォルト）。
    • __pycache__ に .pyc。-O は assert を除去、-OO は assert と docstring を除去。実行は速くならない。
    • dir() は並べ替えたリスト。引数なしは現在の名前（組み込みは含まない → dir(builtins)）。
    • __init__.py でパッケージに。* は __all__ のモジュールだけ。相対インポートは . と ..、メインモジュールでは使えない。

    7.2ファイルの読み書き

    open(ファイル名, モード, encoding=None) はファイルオブジェクトを返します。

    モード意味
    'r'読み込み専用（省略したときの既定）
    'w'書き込み専用。同じ名前のファイルがあると中身は消える
    'a'追記。書き込んだデータは末尾に追加される
    'r+'読み書き両用
    'b' を付ける（'rb' など）バイナリモード。データは bytes として読み書きされる
    • モードを省略するとテキストモードです。テキストモードでは、encoding を指定しないとプラットフォーム依存の文字コードになるので、encoding="utf-8" を指定するのが勧められています。
    • テキストモードでは、読み込み時に行末の改行コード（Windowsなら \r\n）が \n に、書き込み時に \n がプラットフォームの改行コードに変換されます。JPEG や EXE のようなバイナリのファイルを壊さないように、バイナリのファイルはバイナリモードで扱います。
    with 文を使う
    In
    with open('workfile', 'w', encoding="utf-8") as f:
    f.write('This is the first line of the file.\n')
    f.write('Second line of the file\n')
print(f.closed)                  # with を抜けると自動で閉じられる
try:
    f.read()
except ValueError as e:
    print("ValueError:", e)
    Out 
    True
ValueError: I/O operation on closed file.

    with を使うと、処理が終わったとき（途中で例外が起きても）ファイルが正しく閉じられます。with を使わないときは、必ず f.close() を呼びます（閉じないと、データが書き込まれ切らないことがあります）。閉じたファイルを操作すると ValueError です。

    7.2.1ファイルオブジェクトのメソッド

    print(repr(f.read()))        # 全部を1つの文字列で
    print(repr(f.read()))        # ファイルの終わりでは空文字列

    print(repr(f.readline()))    # 1行ずつ。末尾の改行文字は残る
    print(repr(f.readline()))
    print(repr(f.readline()))    # 終わりなら空文字列
    Out 
    'This is the first line of the file.\nSecond line of the file\n'
''
'This is the first line of the file.\n'
'Second line of the file\n'
''
    メソッド動き
    f.read(size)最大 size 文字（バイナリなら size バイト）を読む。省略や負の数なら全部。ファイルの終わりでは ''（空文字列）
    f.readline()1行を読む。末尾の改行文字 \n は残る（最終行に改行がなければ付かない）。'' ならファイルの終わり、'\n' なら空行
    for line in f:1行ずつ回す。メモリ効率がよく、速く、コードも簡単
    list(f) / f.readlines()全行をリストで返す
    f.write(文字列)書き込み、書き込んだ文字数を返す。文字列以外は str() などで変換が必要（バイナリモードなら bytes）
    f.tell()現在の位置を返す（バイナリモードでは先頭からのバイト数。テキストモードでは意味の分からない数値）
    f.seek(offset, whence)位置を変える。whence が 0なら先頭（既定）、1なら現在位置、2なら末尾から offset だけ移動
    In

    for line in f:
        print(line, end='')                  # line の末尾には \n が付いている
print()

18
This is a test
('the answer', 42)
b'5'
b'd' 14

    テキストモードでは、先頭からの seek だけが許されます（例外として seek(0, 2) で末尾へ移動はできる）。有効な offset は f.tell() が返した値か 0 だけです。

    7.2.2構造のあるデータを jsonで保存する

    リストや辞書のような構造のあるデータを、文字列に変換してファイルに保存するには、標準モジュール json を使います。データを文字列にすることをシリアライズ、文字列からデータに戻すことをデシリアライズと呼びます。

    本番で出た論点：json.dump

    4つの関数の違いは、相手が「文字列」か「ファイル」かです。名前の最後の s は string（文字列）の s と覚えます。

    関数動き
    json.dumps(x)x を JSON の文字列にして返す

    9.1名前とオブジェクトについて一言

    オブジェクトには個別性があり、1つのオブジェクトに複数の名前を結び付けられます（他の言語でいう別名＝エイリアス）。数値や文字列のようなイミュータブルなオブジェクトでは気にする必要はありませんが、リストや辞書のようなミュータブルなオブジェクトでは、一方の名前で変更すると他方の名前からも変更が見えます。関数にオブジェクトを渡すときは、実際にはポインタが渡されるだけなので低コストで、関数の中で変更すると呼び出し側にも見えます。

    9.2Pythonのスコープと名前空間

    クラスを理解する前提として、名前空間とスコープの規則を押さえます。
    名前空間

    名前空間は、名前からオブジェクトへの対応付け（マッピング）です。多くは辞書で実装されています。例：組み込み名の集まり、モジュールのグローバルな名前、関数呼び出しのローカルな名前。オブジェクトの属性の集まりも名前空間の一種です。異なる名前空間の名前同士には、まったく関係がありません（2つのモジュールに同じ名前の関数があっても衝突しない）。

    名前空間作られるときなくなるとき
    組み込み名インタープリタの起動時なくならない
    モジュールのグローバル名モジュールの定義が読み込まれたとき通常はインタープリタの終了まで
    関数のローカル名関数が呼ばれたとき関数が return したとき、または処理されない例外を送出したとき

    インタープリタのトップレベルで実行される文は、__main__ というモジュールの一部とみなされます。再帰呼び出しでは、呼び出しごとに別のローカル名前空間ができます。

    スコープ

    スコープは、ある名前空間に直接アクセスできる、プログラムの文面上の範囲です。実行中は、次のスコープが入れ子になっています。名前は内側から順に探されます。

    1. 最も内側のスコープ：ローカルな名前
    2. 外側の関数のスコープ：ローカルでもグローバルでもない名前（nonlocal の対象）
    3. 最後から2番目のスコープ：現在のモジュールのグローバルな名前
    4. 最も外側のスコープ：組み込みの名前
    • global 文で宣言した名前への参照と代入は、モジュールのグローバルスコープに対して行われます。
    • nonlocal 文で宣言した名前は、外側の関数のスコープの変数に再束縛されます。
    • どちらの宣言もない場合、最も内側より外の変数は読み取り専用です。代入すると、内側に新しいローカル変数ができるだけで、外側の同じ名前の変数は変わりません。
    • スコープは文面で（書いた場所で）決まります。代入はデータをコピーせず、名前をオブジェクトに結び付けるだけです。del x はローカル名前空間から x の結び付きを取り除きます。

    9.2.1スコープと名前空間の例

    In
    def scope_test():
    def do_local():
        spam = "local spam"          # do_local のローカル変数が新しくできるだけ
    def do_nonlocal():
        nonlocal spam                # scope_test の spam を書き換える
        spam = "nonlocal spam"
    def do_global():
        global spam                  # モジュールの spam を書き換える
        spam = "global spam"

    spam = "test spam"
    do_local()
    print("After local assignment:", spam)
    do_nonlocal()
    print("After nonlocal assignment:", spam)
    do_global()
    print("After global assignment:", spam)

scope_test()
print("In global scope:", spam)
    Out 
    After local assignment: test spam
After nonlocal assignment: nonlocal spam
After global assignment: nonlocal spam
In global scope: global spam
    • do_local の代入は、scope_test の spam を変えない（ローカル変数を作るだけ）。
    • do_nonlocal の代入は、scope_test の spam を変える。
    • do_global の代入は、モジュールレベルの spam を作る（変える）。scope_test の spam は "nonlocal spam" のまま。
    • グローバルの spam は、do_global を呼ぶ前には存在していませんでした。

    9.3.1クラス定義の構文

    9.3.2クラスオブジェクト

    インスタンスオブジェクトでできるのは属性の参照だけです。属性には、データ属性とメソッドの2種類があります。

    • データ属性（インスタンス変数）は宣言する必要がなく、最初に代入したときに作られます。
    • メソッドは、オブジェクトに属する関数です。x.f はメソッドオブジェクト、MyClass.f は関数オブジェクトで、同じものではありません。

    x.counter = x.counter * 2

print(type(x.f).__name__, type(MyClass.f).__name__)

    16

    In
    class MyClass:
    def f(self):
        return 'hello world'

    9.3.5クラス変数とインスタンス変数

    クラス変数は、そのクラスの全インスタンスで共有される属性とメソッドです。インスタンス変数は、インスタンスごとに固有のデータです。

    In

    クラス変数は Javaの static フィールド、インスタンス変数は普通のフィールドにあたります。ただしPythonでは、インスタンス変数をクラスの中で宣言せず、__init__ の中で self.名前 = 値 と代入して作ります。

    9.4その他いろいろ

    • インスタンスとクラスの両方に同じ名前の属性があると、インスタンスの属性が優先されます。
    • データ属性は、メソッドからだけでなく、利用者（クライアント）からも参照できます。Pythonにはデータを隠蔽する仕組みはなく、すべて慣習に頼っています。
    • メソッドの中からデータ属性や他のメソッドを参照するときに、省略形はありません。必ず self. を付けます。
    • メソッドの第1引数を self と呼ぶのは慣習にすぎません（Pythonにとって特別な意味はない）。ただし、守らないと他の人が読みにくくなります。
    • クラス属性である関数オブジェクトは、すべてメソッドになります。クラス定義の外で定義した関数を、クラスの変数に代入してもかまいません。
    • メソッドは self.メソッド名() で他のメソッドを呼べ、グローバルな名前も参照できます。
    • すべての値はオブジェクトで、クラス（型）を持っています。クラスは オブジェクト.__class__ に入っています。
    In
    def f1(self, x, y):            # クラスの外で定義した関数
    return min(x, x + y)

    f = f1                     # クラス属性に代入するとメソッドになる
    def g(self):
        return 'hello world'
    h = g

c = C()

    i = 1
d = D()

    1 hello world

    9.5継承

    In
    class Animal:
    def speak(self):
        return "..."
    def greet(self):
        return "I say " + self.speak()    # 派生クラスで上書きした speak が呼ばれうる

class Cat(Animal):                        # class 派生クラス名(基底クラス名):
    def speak(self):                      # メソッドのオーバーライド
        return "meow"
    def greet(self):
        return Animal.greet(self) + "!"   # 基底クラスのメソッドを直接呼ぶ

c = Cat()
print(c.greet())
print(isinstance(c, Animal), issubclass(Cat, Animal))
print(issubclass(bool, int), issubclass(float, int))
    Out 
    I say meow!
True True
True False
    • 属性が派生クラスで見つからなければ、基底クラスを探しに行きます（基底クラスがさらに派生クラスなら、その基底クラスへと再帰的に）。
    • 派生クラスは、基底クラスのメソッドをオーバーライド（上書き）できます。基底クラスのメソッドが同じクラスの別のメソッドを呼ぶとき、派生クラスで上書きしたメソッドが呼ばれることがあります（C++でいえば、すべてのメソッドが virtual）。
    • 基底クラスのメソッドを直接呼ぶには、基底クラス名.メソッド名(self, 引数) と書きます。
    • isinstance(obj, int) は、obj.__class__ が int か int の派生クラスなら True。issubclass(bool, int) は True（bool は int の派生クラス）、issubclass(float, int) は False です。

    9.5.1多重継承

    In
    class DerivedClassName(Base1, Base2, Base3):
    ...

    単純な場合、基底クラスから継承した属性は、深さ優先・左から右の順で探されます。階層が重なっている場合でも、同じクラスを2回探すことはありません。つまり、DerivedClassName で見つからなければ Base1 を探し、次に Base1 の基底クラスを（再帰的に）探し、それでも見つからなければ Base2 を探す…という順です。実際には、super() を協調的に呼べるように、メソッドの解決順序（MRO）は動的に決まります。

    In
    class Base1:
    def who(self): return "Base1"
class Base2:
    def who(self): return "Base2"
class Derived(Base1, Base2):
    pass
print(Derived().who())
print([c.__name__ for c in Derived.__mro__])
    Out 
    Base1
['Derived', 'Base1', 'Base2', 'object']

    9.6プライベート変数

    オブジェクトの内部からしかアクセスできない「プライベート」なインスタンス変数は、Pythonには存在しません。ただし、慣習として、アンダースコアで始まる名前（_spam）は、非公開の部分として扱われます。

    サブクラスで定義した名前との衝突を避けるために、名前マングリングという仕組みがあります。__spam（先頭にアンダースコア2つ以上、末尾は1つ以下）という名前は、_クラス名__spam に置き換えられます。

    In
    class Mapping:
    def __init__(self, iterable):
        self.items_list = []
        self.__update(iterable)          # 内部では __update を使う

    def update(self, iterable):
        for item in iterable:
            self.items_list.append(item)

    __update = update                    # 元の update をプライベートにコピー

class MappingSubclass(Mapping):
    def update(self, keys, values):      # update を別の引数で上書きしても
        for item in zip(keys, values):   # __init__ の中の __update は壊れない
            self.items_list.append(item)

m = MappingSubclass([1, 2])
print(m.items_list)
print([n for n in dir(m) if 'update' in n])
print(m._Mapping__update)                # マングリング後の名前ならアクセスできてしまう
    Out 
    [1, 2]
['_Mapping__update', 'update']
<bound method Mapping.update of <__main__.MappingSubclass object at 0x7f14ca948440>>

    名前マングリングは、事故を防ぐための仕組みで、アクセスや変更を完全に禁止するものではありません。exec() や eval() に渡したコードでは、呼び出したクラスのクラス名は考慮されません。

    Javaの private のような強制力はありません。_name は「触らないで」という目印、__name は名前が _クラス名__name に変わるだけです。

    9.8反復子（iterator）

    for 文は、内部でコンテナオブジェクトに iter() を呼びます。返ってくるイテレータオブジェクトは __next__() メソッドを持ち、要素を1つずつ返します。要素がなくなると StopIteration 例外を送出し、for ループが終わります。組み込み関数 next() で __next__() を呼べます。

    In
    s = 'abc'
it = iter(s)
print(it)
print(next(it), next(it), next(it))
try:
    next(it)
except StopIteration:
    print("StopIteration")
    Out 
    <str_ascii_iterator object at 0x7f14cad58d60>
a b c
StopIteration

    自分のクラスにイテレータの動きを持たせるには、__iter__() で __next__() を持つオブジェクトを返すようにします。クラス自身が __next__() を定義しているなら、__iter__() は self を返すだけでかまいません。

    In
    class Reverse:
    """Iterator for looping over a sequence backwards."""
    def __init__(self, data):
        self.data = data
        self.index = len(data)

    def __iter__(self):
        return self

    def __next__(self):
        if self.index == 0:
            raise StopIteration
        self.index = self.index - 1
        return self.data[self.index]

for char in Reverse('spam'):
    print(char, end=' ')
    Out 
    m a p s

    9.9ジェネレータ

    ジェネレータは、イテレータを作るための簡単な道具です。普通の関数と同じように書きますが、値を返すところで yield 文を使います。next() が呼ばれるたびに、前回中断したところから再開します（すべての変数の値と、最後に実行した文を覚えている）。

    In
    def reverse(data):
    for index in range(len(data) - 1, -1, -1):
        yield data[index]

for char in reverse('golf'):
    print(char, end=' ')
print()
g = reverse('ab')
print(next(g), next(g))
    Out 
    f l o g 
b a
    • __iter__() と __next__() が自動で作られるので、クラスより簡潔に書けます。
    • ローカル変数と実行状態は、呼び出しの間で自動的に保存されます。
    • ジェネレータが終わると、自動的に StopIteration が送出されます。

    9.10ジェネレータ式

    リスト内包の角カッコ [ ] を丸カッコ ( ) に変えると、ジェネレータ式になります。外側の関数がすぐにジェネレータを使う場面で使います。リスト内包より機能は少ないですが、リストを作らないのでメモリにやさしいです。関数の唯一の引数として渡すときは、丸カッコを二重にする必要はありません。

    In
    print(sum(i * i for i in range(10)))           # 平方の和
xvec = [10, 20, 30]
yvec = [7, 5, 3]
print(sum(x * y for x, y in zip(xvec, yvec)))  # 内積
data = 'golf'
print(list(data[i] for i in range(len(data) - 1, -1, -1)))
g = (x * 2 for x in range(3))
print(g)                                       # リストではなくジェネレータ
print(list(g), list(g))                        # 一度使い切ると空になる
    Out 
    285
260
['f', 'l', 'o', 'g']
<generator object <genexpr> at 0x7f14ca94e5a0>
[0, 2, 4] []
    POINT
    • 名前空間は名前→オブジェクトの対応。探す順はローカル → 外側の関数 → グローバル → 組み込み。
    • 宣言なしの代入はローカル変数を作るだけ。nonlocal は外側の関数の変数、global はモジュールの変数を書き換える。
    • クラスオブジェクトは属性参照とインスタンス化。データ属性は代入で作られる。x.f() は MyClass.f(x)。
    • クラス変数は共有（ミュータブルは危険）、インスタンス変数は __init__ で self に代入。インスタンス属性が優先。
    • 多重継承は深さ優先・左から右。issubclass(bool, int) は True。
    • __spam は _クラス名__spam に変わる（名前マングリング）。真のプライベートはない。
    • イテレータは __iter__ と __next__、終わりは StopIteration。ジェネレータは yield、ジェネレータ式は ( )。

        self.infile = infile
        self.outfile = outfile

    def run(self):                       # スレッドで実行する処理
        f = zipfile.ZipFile(self.outfile, 'w', zipfile.ZIP_DEFLATED)
        f.write(self.infile)
        f.close()
        print('Finished background zip of:', self.infile)

background = AsyncZip('mydata.txt', 'myarchive.zip')
background.start()                       # スレッドを開始
print('The main program continues to run in foreground.')
background.join()                        # バックグラウンドの処理が終わるのを待つ
print('Main program waited until background was done.')
    Out 
    The main program continues to run in foreground.
Finished background zip of: mydata.txt
Main program waited until background was done.

    上の2行目と3行目の出力順は、スレッドの進み具合によって入れ替わることがあります。

    • start() でスレッドを開始すると run() が実行され、join() でそのスレッドの終了を待ちます。
    • 複数のスレッドでデータを共有するときの調整が難しい点です。threading には、ロック・イベント・条件変数・セマフォなどの同期の仕組みがあります。
    • 推奨されるのは、リソースへのアクセスを1つのスレッドに集中させ、queue モジュールでほかのスレッドからの要求を渡す方法です。Queue オブジェクトを使うと、設計しやすく、読みやすく、信頼性の高いプログラムになります。
    Javaと比べると

    threading.Thread を継承して run() を上書きし、start() と join() を呼ぶ流れは、Javaの Thread クラスとまったく同じです。queue.Queue は BlockingQueue にあたります。

    Pythonは自動でメモリを管理します（多くのオブジェクトは参照カウント、循環参照はガベージコレクションで解放）。最後の参照がなくなると、すぐにメモリが解放されます。

    12.1イントロダクション

    Pythonのアプリケーションは、標準ライブラリにないパッケージやモジュールを使うことがよくあります。さらに、ライブラリの特定のバージョンが必要になることもあります（あるバグが直っている版や、古いインターフェイスで書かれている版など）。

    そのため、1つのPythonのインストールで、すべてのアプリケーションの要求を満たすことはできない場合があります。例えば、アプリケーションAはあるモジュールのバージョン1.0を、アプリケーションBはバージョン2.0を必要とすると、どちらかが動かなくなります。

    これを解決するのが仮想環境です。仮想環境は、特定のバージョンのPythonと、いくつかの追加パッケージを含む、自己完結したディレクトリツリーです。アプリケーションごとに別の仮想環境を使えば、要求がぶつかりません。

    12.2仮想環境の生成

    仮想環境の作成と管理には、venv モジュールを使います。venv は、そのコマンドを実行したPythonのバージョン（--version で表示されるもの）をインストールします。
